## 1. 概要

### 1.1 コンセプト

> **「ゲームをしていたら、日本語が自然と入っていた」**
> ゆるく続けられる、かわいくて楽しい日本語学習アプリ。

キャラクターと会話しながら、2択をスワイプで選ぶだけでストーリーが進む。
「ゲームオーバーなし」「書かせない」「入力させない」を軸に、心理的負担を極限まで下げる。

### 1.2 ターゲット

- 日本語学習者(外国人)。初級〜中級(N5〜N3 想定)
- 机に向かう学習が続かない人、スキマ時間(1 シーン 30 秒〜1 分)で触りたい人

### 1.3 Duolingo との差別化

| 観点 | Duolingo 型 | 本アプリ |
|---|---|---|
| 間違えたとき | ハートが減る/やり直し | **ゲームオーバーなし**。反応が変わるだけ |
| 学習単位 | 単語・文の問題 | **シチュエーション+キャラとの会話** |
| 入力 | 選択・入力・発話 | **上下スワイプのみ**(書かせない) |
| 動機 | 連続日数・ハート | **キャラとの好感度・マルチエンディング** |
| 学び方 | 正誤判定 | 「相手が喜ぶ/困る」という**体験**で学ぶ |
| 世界観 | 汎用 | 日常の場面ごとのステージ+かわいいキャラ |

### 1.4 設計原則

1. **直感的・シンプル**: 操作は上下スワイプとタップのみ
2. **ゲームオーバーなし**: どの選択でも話は進む。失敗は「学びのリアクション」になる
3. **書かせない**: 文字入力・手書きは採用しない
4. **ゆるく続く**: 1 シーン 30 秒〜1 分。ストリークで煽らない
5. **データ駆動**: シーン追加=データ追加。アップデートで増やせる構造
6. **簡易版から**: 絵は静止画パターン切替。アニメーションは作り込まない

## 3. ゲーム構造

### 3.1 階層

```
アプリ
 └─ ステージ(家 / コンビニ / 駅 / カフェ …)  ← アップデートで追加
     └─ キャラクター(母 / 妹 / 猫 / …)       ← 他ステージにも再登場
         └─ 会話シーン(ノード分岐のストーリー)
              └─ エンディング(好感度などで分岐)→ サマリー
```

### 3.2 基本ループ

```
ステージ選択
  → キャラ選択(そのステージの全キャラ)
  → 会話シーン(会話フェーズ ⇄ 選択フェーズ を繰り返す)
  → エンディング
  → サマリー(学んだ表現の解説)
  → キャラ選択へ戻る
  → 全キャラと会話完了でステージクリア → 次ステージ解放
```

- ステージごとのキャラ数は可変(固定 5 人にはしない)
- 同一キャラは複数ステージに登場してよい(関係性が引き継がれる)
- エンディングはキャラごとに複数。リプレイで別ルートを見たくなる設計

## 5. 会話画面(S05)仕様

### 5.1 レイアウト(縦画面)

```
┌───────────────────────────┐
│ 「家」 〜 母との朝 〜  ♥♥♡ │ ← ステータス帯(テーマ/シーン名/好感度)
│───────────────────────────│
│ ▲ 上の選択肢エリア        │ ← 選択フェーズで色づく+文章表示
│                           │
│   [背景]                  │
│       [キャラ上半身]      │ ← 中央配置
│                           │
│          ◆                │ ← ふわふわアイコン(小さめ)
│                           │
│ ┌───────────────────────┐ │
│ │ ダイアログ(会話文)    │ │ ← 会話フェーズのみ表示
│ └───────────────────────┘ │
│ ▼ 下の選択肢エリア        │ ← 選択フェーズで色づく+文章表示
└───────────────────────────┘
```

- キャラの上に**ステータス帯**(テーマ「コンビニにて」、シーン名、好感度など)を簡易表示
- 背景はステージ(場所)ごと、キャラは上半身を中央に配置
- 下部に会話ダイアログ。選択フェーズに入ると**ダイアログは消える**

### 5.2 フェーズ

#### 会話フェーズ

- キャラのセリフがダイアログに表示される(タップで次へ/自動送りは設定可)
- セリフは TTS で読み上げ(設定でオフ可)
- 単語に**下線**。タップで解説ポップアップ(第 7.4 節)
- アイコンは画面内を**ふわふわ漂う**(無重力)
- ユーザーがスワイプすると、アイコンが**エアホッケーのように弾んで**画面内を動く(壁反射・減衰)。手遊び要素であり、進行には影響しない

#### 選択フェーズ

1. ダイアログが消える
2. **上下のエリアが色づき**、各選択肢の文が表示される
3. アイコンが**画面中央へふわっと移動**して待機
4. ユーザーがアイコンを**上または下へスワイプ(投げる)**して選択を確定
5. アイコンが選んだ側へ飛び、リアクション演出へ

- 選択肢は常に **2 択**(上/下)
- 投げる前の**プレビュー**: ドラッグ中、近づいた側のエリアが強調される
- 途中キャンセル可: 閾値未満で離すと中央に戻る

#### リアクションフェーズ

- キャラの表情を切り替え(通常/笑顔/困り顔/驚き など)
- 効果音とエフェクト、好感度の増減表示
- セリフで反応(「えらい!」「あ、それは…」など)→ 次の会話フェーズへ

### 5.3 ふわふわアイコン

- 場面ごとにモチーフが変わる(例: 家=湯呑み、コンビニ=おにぎり、駅=切符)
- サイズは小さめ(画面幅の 1/8〜1/6 程度)
- 会話フェーズ: ランダムな微速度で漂う+ユーザーのスワイプで弾む
- 選択フェーズ: 中央へ補間移動 → スワイプ方向・速度で上下判定
- 実装方針は第 10 章(SpriteKit 想定)

### 5.4 オンボーディング(S02)

初回のみ、**実際に触って覚える**形式。説明文は最小限。

1. アイコンをスワイプして弾ませる(「ふわふわをなでてみよう」)
2. ダミーの 2 択で上/下に投げる(「上か下に投げて選ぼう」)
3. 下線をタップして解説を見る(「下線をタップすると意味がわかるよ」)
4. 失敗しても大丈夫と伝える(ダミーで不正解を体験 → ゲームオーバーなし)
5. ステージ選択へ

- スキップ可。設定から再表示可
- UI 言語は英語を基本、日本語表記にはローマ字/英訳の併記を選べる

## 6. ゲームルール

### 6.1 選択肢の評価

各選択肢は 3 段階で評価する(内部データ)。

| 評価 | 意味 | 演出 | 好感度 |
|---|---|---|---|
| `best` | 状況に最適な表現 | 笑顔、派手なエフェクト | +2 |
| `ok` | 通じるが最適ではない | 普通の反応 | +0 |
| `bad` | 文化的/敬語的にマズい | 困り顔・やさしい指摘 | −1 |

- 2 択の組み合わせは `best / bad` を基本に、`best / ok` `ok / bad` も許容
- 「bad」でも**ゲームオーバーにしない**。話は進み、キャラが理由をやさしく伝える
- 文化的な反応(「外国人なのに敬語知ってる!」など)で、正誤ではなく「相手が喜ぶ」体験にする

### 6.2 好感度

- キャラごとに数値管理(ハート 0〜5 段階表示)
- 他ステージでも同キャラの好感度を引き継ぐ
- 好感度に応じて、エンディングの種類・セリフ・表情が変わる

### 6.3 マルチエンディング

- シーン内の評価履歴と好感度でエンディングを決定(例: 通常/ベスト/おしい)
- 到達済みエンディングを記録し、キャラ選択画面で達成度を表示(コンプ欲)

## 7. 学習設計

### 7.1 学習テーマ(ステージ・キャラ別)

- 敬語(丁寧語/尊敬語/謙譲語)とカジュアルの使い分け
- 日常表現・あいさつ・お願い・断り方
- 相手(家族/店員/友人/目上)による言葉の切り替え
- 日本の生活習慣・マナー

### 7.2 反応による学習

- 正誤を点数で突きつけず、**キャラの反応と好感度**で伝える
- bad の場合は短い「ひとこと解説」をキャラのセリフ/吹き出しで添える

### 7.3 シーン後サマリー(S06)

エンディング後に表示するカード形式の解説。

- 今回使われた重要表現(最大 5 個程度)
- 各表現: 日本語 / 読み / ローマ字 / 英訳 / 使いどころ / 丁寧さレベル
- 自分が選んだ表現が `best` / `bad` だった場合は対比を表示(「こう言うと自然」)
- 「語彙リストに保存」ボタン、TTS 再生ボタン

### 7.4 下線タップ解説(会話中)

- セリフ内の学習対象語(`notes` で指定)に下線
- タップでポップアップ: 意味・読み・用法・敬語レベル・TTS
- 解説は日本語を読めなくても理解できるよう、英訳/ローマ字の表示を切り替え可能
- 解説データはシーンのデータに含める(第 9 章)

### 7.5 音声(TTS)

- 方針: **TTS(AVSpeechSynthesizer)を採用**。録音ファイルは管理コストが高く、セリフ変更が多い開発に不向き
- キャラごとに声の高さ(pitch)・速度(rate)を変えて個性を出す
- 学習者向けにゆっくり再生(0.5x/0.75x)を選べるようにする
- 重要セリフのみ将来的に録音差し替え可能な設計(`audio` フィールドを任意で追加できる)

## 9. データ設計

### 9.1 方針

- ステージ・キャラ・シーンは**JSON(バンドル内)で管理**。シーン追加=ファイル追加
- ストーリーの本文は**AI で生成**し、スキーマに沿ったJSONとして取り込む(第 12 章)
- ユーザー進捗(好感度・到達エンディング・保存語彙)は端末内に保存

### 9.2 ディレクトリ案(コンテンツ)

```
Content/
 ├─ stages.json                 ステージ定義
 ├─ characters.json             キャラ定義(共通)
 └─ scenes/
     └─ home/
         ├─ mother_morning.json
         └─ sister_chat.json
```

### 9.3 スキーマ(案)

```jsonc
// stages.json
{
  "id": "home",
  "title": { "ja": "家", "en": "Home" },
  "background": "bg_home",
  "floatIcon": "icon_teacup",
  "characters": ["mother", "sister", "cat"],
  "level": "N5"
}

// characters.json
{
  "id": "mother",
  "name": { "ja": "お母さん", "en": "Mother" },
  "kind": "human",              // human | animal
  "assetPrefix": "mother",      // mother-normal / -happy / -sad / -surprised
  "voice": { "pitch": 1.1, "rate": 0.45 },
  "profile": { "en": "Warm and a little strict about manners." }
}

// scenes/home/mother_morning.json
{
  "id": "home_mother_morning",
  "stage": "home",
  "character": "mother",
  "title": { "ja": "朝のあいさつ", "en": "Morning greeting" },
  "level": "N5",
  "start": "n1",
  "nodes": {
    "n1": {
      "type": "line",
      "speaker": "mother",
      "expression": "normal",
      "text": "おはよう。よく眠れた?",
      "notes": [
        { "range": [0, 4], "id": "ohayou" },
        { "range": [6, 9], "id": "yoku_nemureta" }
      ],
      "next": "n2"
    },
    "n2": {
      "type": "choice",
      "prompt": "どう答える?",
      "up":   { "text": "はい、よく眠れました。",   "rating": "best", "affinity": 2,  "next": "n3a" },
      "down": { "text": "うん、ねむい〜。",         "rating": "ok",   "affinity": 0,  "next": "n3b" }
    },
    "n3a": { "type": "line", "speaker": "mother", "expression": "happy", "text": "ていねいね。えらい!", "next": "end_best" },
    "n3b": { "type": "line", "speaker": "mother", "expression": "normal", "text": "ふふ、まだ眠そうね。", "next": "end_normal" },
    "end_best":   { "type": "ending", "id": "best",   "summary": ["ohayou", "yoku_nemureta"] },
    "end_normal": { "type": "ending", "id": "normal", "summary": ["ohayou"] }
  },
  "notes": {
    "ohayou": {
      "ja": "おはよう", "reading": "ohayou",
      "en": "Good morning (casual)",
      "usage": { "en": "Use 'おはようございます' with seniors or strangers." },
      "politeness": "casual"
    }
  }
}
```

### 9.4 ユーザー進捗モデル(端末保存)

- `CharacterProgress`: characterId, affinity
- `SceneProgress`: sceneId, reachedEndings[], lastPlayedAt
- `SavedExpression`: noteId, savedAt, reviewCount
- `AppSettings`: ttsEnabled, ttsRate, showRomaji, showEnglish, darkMode…

## 10. 技術設計

### 10.1 技術スタック(案)

| 領域 | 採用案 | 理由 |
|---|---|---|
| 言語/UI | Swift / SwiftUI | 画面遷移・UI構築が速い |
| アイコン物理 | SpriteKit(`SpriteView` で SwiftUI に埋め込み) | 重力0・反発・減衰・衝突が標準で使える。エアホッケー表現に最適 |
| 音声 | AVSpeechSynthesizer(`ja-JP`) | 録音管理不要 |
| 効果音/触覚 | AVAudioEngine / UIImpactFeedbackGenerator | 軽量 |
| データ保存 | SwiftData(または UserDefaults+Codable) | 進捗は小規模 |
| コンテンツ | JSON(Codable) | データ駆動 |
| 最低 OS | iOS 17 以上を想定(SwiftData 利用のため) | 要確認 |

### 10.2 アーキテクチャ

- 軽量な MVVM+状態機械。外部依存は極力持たない

```
View(SwiftUI)
  ├ StageSelectView / CharacterSelectView / SummaryView …
  └ ConversationView
       ├ BackgroundLayer / CharacterLayer / StatusBar / DialogView
       ├ ChoiceOverlay(上下エリア)
       └ FloatingIconScene(SpriteKit)
ViewModel
  ├ ConversationViewModel(状態機械: line → choice → reaction → … → ending)
  └ ProgressStore(好感度・エンディング・語彙)
Service
  ├ ContentLoader(JSON → モデル)
  ├ SpeechService(TTS)
  └ FeedbackService(音・ハプティクス)
```

### 10.3 会話の状態機械

```
idle → showLine → (タップ) → [next node]
                         ├ line   → showLine
                         ├ choice → choosing(アイコン中央へ)→ thrown(up/down) → reaction → [next node]
                         └ ending → summary
```

### 10.4 スワイプ判定

- アイコンへのドラッグ終了時の**速度ベクトル**で判定
- Y 方向の速度が閾値以上 → 上/下確定。閾値未満 → 中央へ復帰
- 左右成分が大きい場合は無効(誤操作防止)
- ドラッグ中の Y 位置に応じて、上/下エリアを強調(プレビュー)

### 10.5 パフォーマンス/品質

- 画像は Asset Catalog。背景は大きいので JPG/HEIC も検討
- TTS は事前にウォームアップし、初回遅延を抑える
- VoiceOver・Dynamic Type 対応(ただしゲームUIは固定要素あり。優先度中)

## 11. アセット仕様

### 11.2 仕様

| 種別 | 形式 | 制作サイズ(@3x 原画) | 備考 |
|---|---|---|---|
| キャラ(上半身) | PNG(透過) | 1200×1500 px | 全表情で**同一キャンバス・同一位置**。切替時にズレない |
| 背景 | PNG または JPG | 1290×2796 px(縦) | キャラを邪魔しない彩度。中央にキャラが来る |
| アイコン | PNG(透過) | 300×300 px | 画面上では小さく表示 |

- 表情は最小 `normal / happy / sad(困り) / surprised` の 4 種を目安に。動物キャラも同様
- 1 キャラ=1 セット。**他ステージでも再利用**するため、衣装差分は後回し
- 以前チャットで示したピクセル数(400×600 等)は 1x 基準の目安。**制作は @3x 原画を基準**とし、本表を正とする

### 11.3 生成プロンプトの方針(ChatGPT 等の画像生成用)

画像生成は別ファイルで管理する(例: `docs/asset-prompts.md`)。共通ルール:

- **画風を固定**: 全キャラ・背景で共通のスタイル文(線の太さ、色数、柔らかい塗り)をプロンプト冒頭に固定する
- キャラは「同一キャラ・同一構図・表情のみ変更」と明記し、1 キャラ 4 表情を連続で生成
- 背景は「人物なし」「中央に空間を残す」と明記
- 透過PNGが出ない場合は単色背景で生成し、後処理で切り抜く

## 12. コンテンツ制作・AI ストーリー生成

- ストーリー本文は AI で生成する。**v1.0 は仮ストーリーで構成・UX の検証を優先**
- 生成は「スキーマ準拠 JSON」を出力させ、取り込み前に自動検証する
  - ノード参照切れ、`rating` 値、`notes` の範囲指定ミスをチェック
- 生成プロンプトに含める要素: ステージ/キャラ設定、レベル(N5 等)、学習テーマ、2択の `best/bad` 設計、1 シーンの長さ(会話 6〜10 ターン、選択 2〜3 回)、語彙数
- **日本語ネイティブによるレビュー工程を必須**とする(不自然な敬語・文化的誤りの混入防止)
- 新ステージ追加の手順: ①ステージ/キャラ定義 → ②AI でシーン生成 → ③検証・レビュー → ④アセット追加 → ⑤アップデート配信
